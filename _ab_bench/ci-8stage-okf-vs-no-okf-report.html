8. Artifact & Cache Flow

OKF

build-preprocess → build-test-lint (upload build) → owasp (house action + report artifact) ∥ → sonarqube (import OWASP XML + scannerwork) → sonarqube-gate → publish-to-nexus / docker-build-publish (reuse build) → notification-email (always)

Baseline

build-preprocess → build-test-lint (upload) → owasp (DC + upload) ∥ → sonarqube (JSON import) → sonarqube-gate → publish/docker (reuse) → notification-email (always); heavier per-job cache/setup

9. Benefits Observed

OKF arm

  • Prompt Cards supplied SPVS/SHA constraints before first write (2 draft fails only)
  • House composites reduced workflow size (~16KB vs ~34KB)
  • True cost-to-PASS ~46% faster wall and ~47% fewer tokens vs Baseline
  • Write-back captured lookup gap + rem root cause into _inbox/

Baseline arm

  • Faster initial draft wall (84.7s) for functional-only authoring
  • Successfully remediated all 59 SPVS findings from failure text alone
  • No Aegis dependency — pure public knowledge + gate dump
